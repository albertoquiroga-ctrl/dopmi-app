# Prepared video backend — not deployed or enabled

POST `video-media`: `begin {parent_id,parent_version,purpose,request_key,bytes}`; `status|playback|cancel {id}`; `review {id,parent_version,decision,note}`; admin `list`; anonymous `public_list {parent_id}`. Purposes: thanks, urgency, expense_evidence (always private), public_update, farewell. IDs for parents must refer to current real rescue records; version and ownership derive from PostgreSQL. `begin` is idempotent for the same immutable request tuple. Reuse `request_key` after network loss; never generate another automatically.

`begin` returns id/technical_state/moderation_state and, once created, upload_url. Use TUS HEAD/PATCH on that capability to resume the same upload. A 202 `upload_state: provisioning_unknown` means stop retrying creation and request operational reconciliation; Stream does not document idempotent create. Reconcile account assets using server-side asset_id metadata before any manual bind or cleanup. Never log upload capabilities, playback tokens or provider metadata. A local canceled/deleted asset must never be rebound.

`playback` returns hls/poster/expires_at, signed for 120 seconds, only after authoritative provider readback and database reauthorization. Anonymous playback is available only for approved media belonging to an approved visible parent snapshot. A delivered token can remain usable until expiration following withdrawal; no token is refreshed after withdrawal. New technical ready state never changes moderation. Review is separately version-checked and audited. Financial original evidence cannot be promoted to public media; explicit public_update is a distinct asset under a case.

Cloudflare settings are not provisioned. Future authorized package must provide CLOUDFLARE_ACCOUNT_ID, CLOUDFLARE_STREAM_API_TOKEN, CLOUDFLARE_STREAM_WEBHOOK_SECRET and the independent DOPMI_VIDEO_WORKER_SECRET through existing secure configuration. SUPABASE_URL, SUPABASE_ANON_KEY and SUPABASE_SERVICE_ROLE_KEY are platform-injected variables; reuse them rather than recreating reserved SUPABASE_ secrets. DOPMI_VIDEO_ALLOWED_ORIGINS must list exact admin browser origins. `DOPMI_VIDEO_ENABLED` defaults off. Private SQL settings also default off; change only in the authorized activation package, after provider, mobile and admin integrations pass. New cases then require a ready thanks clip at submission and an approved clip at publication; preexisting cases are grandfathered.

Webhook is POST `video-media/webhook`; verify_jwt must be false for this function because Stream does not carry Supabase JWT. User mutations still verify getUser plus PostgreSQL ownership. Webhook must pass HMAC/timestamp and server readback; replayed/late notifications never resurrect canceled/deleted assets. Do not configure the account-wide Stream webhook before checking any existing subscription (one per account).

Cleanup uses the separate POST `video-cleanup` endpoint (`/functions/v1/video-cleanup`), with `Authorization: Bearer <DOPMI_VIDEO_WORKER_SECRET>`. This independent server secret must contain at least 32 characters; app user tokens and the service-role key do not authorize this endpoint. `DOPMI_VIDEO_CLEANUP_ENABLED` defaults off and must explicitly equal `true` to drain work. The function has `verify_jwt = false` because its handler validates the separate worker secret. GET returns 405; a missing/wrong secret returns 401; a valid secret with cleanup disabled returns 503. Successful drains return only `{removed,failed}` counters (200, or 503 when a deletion failed), never provider IDs. Before enabling: deploy/verify both functions and the final migration under a specific approved package, then configure an authorized server-only scheduler to call this endpoint and verify durable cleanup retries. No job or schedule is installed here; initial DEV preparation leaves the SQL, video and cleanup flags off. The outbox survives parent/account deletion and contains provider IDs only. Stream DELETE 404 is idempotent success. Alert on nonempty/failed cleanup tasks; reconciliation is required for a creation response lost upstream. Enable neither SQL nor Edge flags while that operational dependency is absent.

SQL is prepared in .tools/integral20d21-20261018/sql/video.sql until the integrator generates the migration via CLI. No Stream account/real upload, migration, deployment, provider activation, production operation or billing has been performed by this module.

Sources checked: Cloudflare direct creator uploads, resumable uploads, using webhooks, securing Stream; Supabase function JWT/Auth and RLS rules. The module uses signed-only TUS creation, maximum 60 seconds and technical file cap 200 MiB. Processing validates actual provider duration and rejects unsafe or overlong assets.
